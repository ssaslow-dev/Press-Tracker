# REQ-6 A TinyFish fetch failure silently drops candidates as "not naming Gabriel"

Patch: `patches/REQ-6_fetch_retry.patch` (`code/tracker/41_update_search.js`, 4 zero-context hunks; applies cleanly to pristine L/code and on top of REQ-2 (offset 10), checked). Test: `patches/tests/test_fetch_retry_js.js`.
Change: the open-pages loop becomes two passes (`for (let pass = 0; pass < 2; pass++)`; pass 0 = all `toFetch` in batches of 10, pass 1 = the `_fetchfail` ones in batches of 5, same `tfFetchInput`). A thrown fetch (not a STOP code) sets `c._fetchfail = true` on every candidate of the batch instead of `U.failed++`; a batch that returns clears the flag for its candidates. After the passes `U.failed++` once per still-flagged candidate. The `drop.forEach` reason becomes 'Its page could not be fetched (TinyFish error), so it was not judged. Try again later.' for `_fetchfail` candidates; fetched-and-not-naming-him candidates keep the old reasons (blocked / "isn't named").
Deviation from the request text: its test says the first call throws `{code:'server_unavailable', retryable:true}`; `tfCall` already retries a retryable error once itself (41 lines 14-18), so that case never reaches the new code. The test throws a non-retryable `{code:'tool_error'}` (the case that did drop pages). Candidates are a result whose snippet says only "Gabriel said ..." (passes the any-script filter, not the full-name test) and whose page names "Assemblymember Jesse Gabriel, D-Encino".
Results (playwright, patched page built in scratch_root; `REQ-6/test_patched.log`): 12 checks, FAILS 0. (1) first fetch throws, retry reads the page: 2 attempts, find kept (in rows/unconfirmed), not in the left-out list, `failed` equals the clean-fetch run; (2) both throw: exactly 2 attempts, final run doc's `left` carries the new reason, nothing added, `failed` = clean + 1 (counted per page), `#updBody` textContent shows the reason (the list sits in a closed `<details>`, so innerText would not; use textContent); (3) page read and not naming him keeps "isn't named" reason.
Negative control on the unpatched page (`REQ-6/negative_control_unpatched.log`): FAILS 8, reproducing the bug (1 attempt, find in `left` with "Gabriel isn't named in the page text or the search snippet", `failed` +1 for the whole batch of 1).
Notes: the 2% gate behaves as before in the fake world (3 of 716). A pass-1 retry costs one TinyFish slot (2.1 s) per 5 pages. No full run_all was done for this patch alone (only the three scenarios above); it was applied to the same scratch tree that ran REQ-2/3's full suite earlier.
