# REQ-7 has_work counts orphan pages docs as work

Patch: `patches/REQ-7_has_work_pages.patch` (`code/sheet_task.py` `has_work`, plus one line in `build/tests/run_all.sh`). Test: `patches/tests/test_has_work_pages.py`.
Change: `why['pages']` now counts only pages docs that something still points at; `why['pages_orphan']` = the rest; `any(...)` ignores `pages_orphan`. A pages doc is referenced when its key equals, for a run with `not run_done(run)`, any row's `Article ID`, `Story ID`, `Tracker story code` (whole value and every `jg-xxxxxx` in it), `_page`, `_ph_sid`, or an `_origin.cands[*].page`; or, for a reprints doc without `aid`, `'rp-' + <doc id>` (also the bare id, `rp:<id>`, and the doc's own `_pageKey`, which 41 line 972 writes for folded finds - my addition to your list). Keys follow `page_doc_id` / `apply_origin` in sheet_task.py.
Results: `test_has_work_pages.py` 10 checks, ALL PASS on the patched code (`REQ-7/test_b.log`): applied run (ids set) + 2 orphan pages -> `has_work` False, `pages_orphan` 2; a run with only a sheet line counts as applied; the same pages with the run undone (ids removed) -> True, pages 2, orphan 0, runs 1; a single orphan alone -> False; placeholder / `jg-` code keys count, a stray one is an orphan; unwritten reprints doc keeps `rp-<id>` (and `_pageKey`) as work, a written one leaves it an orphan; bills_new still work; empty db -> `{runs 0, bills 0, releases 0, edits 0, reprints 0, pages 0, pages_orphan 0}`. Unpatched code fails checks 1 and 1b and then raises KeyError on `pages_orphan` (`REQ-7/test_a.log`).
Existing suites with the patch (together with REQ-3, scratch root): test_sheet_task 50/50, test_relbutton 44/44, test_final_int 22/22, test_coldstart_f1 all PASS.
