## What the patch does (as specified, plus the points below)
- 43: `saveRun` on missing `runsCol` or a throwing `set` keeps the doc in `localStorage['jg-runs-pending']` (array, last 5, `rows[*]._text` stripped), sets `LOG.lastSaveError = {code, message}`, returns false. New `runHeartbeat(id, patch)` (doc: at, mode, status 'running', provisional true, heartbeat ISO + patch). `cleanRun` passes status (VS 20), step (120), error (300), heartbeat, failed, done/plan/cands numbers, `unconfirmed` (<=150 of {hl,outlet,date,link,why}). Log panel: "Running since <at>, <done> of <plan> searches" / "Stopped: <error>" / `unconfirmed` section; a running doc whose heartbeat is >30 min old reads "No progress since ... the tab was probably closed" (my addition, so a dead tab does not show "running" forever).
- 42 `runAll`: heartbeat `{step:'start'}` before `runUpdate()`; if false, find-step note = the "Run log unavailable ..." text, `RA.noStore = true` (text also appended to the find step's final note so it is not overwritten); body after `RA.run = newRunId()` wrapped in try/catch inside the outer try: error -> first running step (all running steps) set to warn "Stopped by an error: ...", error doc `{status:'error', error, rows}` saved, return (finally still runs); final `saveRun` has `status:'done'` and `unconfirmed`; `const saved`; if `!saved`: sheet step warn with the specified text and return, no `fire_trigger` (this check runs BEFORE the "Nothing new to write" early return, because scenario B has nothing found and still expects the sheet warning).
- 41: `hbTick()` (fire-and-forget, at most one write per 20 s, queued on a promise chain, never awaited inside `tfCall`), called every 25 completed searches in the worker and at each later phase `U.step` change (TV captions, Google News, Opening pages, outlet origin, reprint text check, LegInfo); `saveSheet`: `if (!await saveRun(...)) toast(...); return`.

## Design points the reviewer should check (deviations / additions)
1. Heartbeat vs the existing provisional doc: `set` replaces the whole doc, so a late heartbeat would erase the provisional doc's `stories/rows` written by `saveFound`. I added `RA.hbOff` (set before saveFound's provisional write and before the final saveRun) and `hbFlush()` (await the heartbeat promise chain) so no progress write can land after, or replace, those docs. The provisional doc now also carries `status:'running'` and `heartbeat`.
2. Heartbeat docs have no `rows`/`ids`, so `sheet_task.has_work` (counts runs with `rows` and not `run_done`) does not treat them as work; an error doc WITH rows is work, intentionally (next press picks it up) but the sheet task is not fired for it.
3. `failed` is the string "n of m" in the final doc (unchanged) and a number in heartbeats; `cleanRun` stringifies it (VS 20).
4. Scenario A has `use('mcp')` throwing `server_not_connected` for everything, so the run ends at the first TinyFish call; the "status running before any TinyFish call" check compares the index in `__sets` with the call count recorded at that moment (0).
