# Cleaning playbook — learned from finished buckets (read, reuse, add to it)

Finished: bucket 6 (agent-clean-6, 350 files in ~15 min), buckets 1 and 3 (logs complete). Their code is readable: L/work/tmp_agent-clean-6/clean6.py (cleaner) and mac_run.py (Mac runner); also L/work/tmp_agent-clean-1/, tmp_agent-clean-3/. Status logs in L/status/.

## Fastest workflow (bucket 6)
1. Stage ALL your originals into the container once (device_stage_files, 50 per call) and verify checksums — no per-file Mac round trips.
2. Build and test cleaners in the container, per outlet template; render-check samples with Playwright.
3. Ship the cleaner + a file list to the Mac ONCE and run it there in one device_bash call (backup to _original_html first, then write); dry-run on the Mac first and compare sha256 of outputs with the container's.
4. Copy the results to L/work/html_clean/.
Scratch files on the Mac go in $HOME/mnt/outputs, never in the Tracker library.

## Reusable patterns (outlets repeat across buckets — reuse before writing new rules)
- Epoch Times / 大紀元: "share / related / rankings / comments" tail, view counters, font UI.
- The Hill: "More News / Hill.TV / Top Stories" tails.
- Korea Times: comment policy, reader comments, login box.
- WordPress blogs: archive lists, recent posts, subscribe widgets.
- Sing Tao: FlippingBook viewer junk.
- Image ads: match by exact image hash after looking at them (e.g. SFV Sun "No on Prop 44").
- Safety-check false positives: login-box headings, comment headings, tags matched as "headline" — exclude those from the headline check.
- Header metadata: remove lines whose outlet+date or URL already match the sheet; keep "Saved …" lines (no column).
- Never remove by broad trigger words ("newsletter", "subscribe", "courtesy of", "latest news", "comments") — real articles use them; never remove a phrase just because it recurs across many stories (e.g. "Assemblymember Jesse Gabriel (D-Encino)"): a 2026-10-26 trial that did removed real syndicated text. Site chrome = text repeated word for word on the same outlet's unrelated pages. (From the retired "Reprint info" tab, OUTLETRULES-v1 gap-fill.)

## Merged cleaner (T37, agent-code, 2026-10-27; Python only since DECISIONS 2026-10-27 "no browser (JS) cleaner") — what later runs use
- One cleaner for library files, new finds and press-release copies: `code/clean_html.py` (Python), run by the sheet task when it saves a page (pipeline file `clean_html.py`). The Update button does not clean in the browser; previews right after Update may show clutter until the rebuild. `code/clean_html.js` (the old browser port) is no longer a pipeline file or an apply_all step and is not kept in step with the Python rules. Rules are data: `code/clean_rules.json`. Library-only one-off decisions of the buckets: `code/clean_overrides.json` (keyed by `<year>/<old Article ID>`; never used for new finds).
- A page is split into text blocks (text inside one block element, split at `<br>`). Rules match a WHOLE block (regex, JS-compatible; a leading `(?i)` = ignore case):
  - `generic` (every page) and `sites[<host>]` (pages of that host; the outlet name is used only when no host matches): `kill` (drop the block), `tail` (drop it and everything after it, only after the article's h1), `head: "h1"` (drop everything before the h1), `strip` (drop the matching part of a block), `img` (12-hex sha1 of an image src), `lkill`/`ltail` (match on lowercase text with digit runs as #), `cut` [start, end, include_end], `section` [heading, max words], `drop` {tag, attr, re}, `allow_long`, `allow_big`.
  - `find` (TinyFish-format pages = new finds and re-fetches; mode find only): `head`, `tail`, `kill`, `repeat_title`, `tidy` (agent-retry's post-pass); blocks naming Gabriel are never removed by these. `comments_strong` / `comments` / `related`: a comment section or end-of-page teaser list is OUTSIDE the article and is removed even when it names Gabriel, so a page naming him only there is flagged `gabriel_outside_article` and the find is SKIPPED.
  - `outlet_aliases`: header outlet names the buckets treated as the sheet's outlet (header lines).
- Safety (always): a removed block of >= 40 words of prose is kept (flag long_block) unless the site allows it; > 35% of words removed -> the page is left as it was (flag big_removal); Gabriel in any script (가브리엘, Габриэл, גבריאל, 加布里埃尔/爾 …; "San Gabriel" is not him): if every mention would go, library files keep those blocks; finds are skipped.
- Header lines (first `<div>`: "Outlet · date", URL, "Saved …"): removed when equal to the sheet, kept and reported otherwise; "Saved" is kept.
- To add a rule: put it in `clean_rules.json` under the site's host (or `generic` / `find`), then run only the tests the change touches (DECISIONS 2026-10-27, "NO full routine"): spot-check the pages of that site with `clean_html.py`. The full regressions in work/tmp_agent-code/ (`regress.py` library vs work/html_clean, `regress_retry.py` TinyFish pages, `findscan.py` skip/error scan) run once at the end of a round, not per rule. The Python/JS parity test (`build/test_clean/test_clean.js`) is dropped. A rule must never remove a block the buckets kept.
- After editing clean_rules.json or clean_html.py, run `python3 code/apply_all_patches.py` so build/pub/pipeline/ carries the change (README, "Code path").
