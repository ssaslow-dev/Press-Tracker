# AJG Project Library — start here

The shared library for every chat and agent working on the AJG press-coverage project. Read this file, then the files it lists, before doing anything.

Owner: Sammy. Coordinator: the chat linked to Sammy's Mac. It plans, dispatches, records and reports; every piece of work, including Mac writes, builds and publishes, goes to a background agent (DECISIONS 2026-10-27, "coordinator chat stays free").

## 3. Rules for parallel work

1. **One writer for Sammy's files.** Writes to Sammy's Mac and artifact publishes happen only through the coordinator: either the coordinator or a background agent it has dispatched for that write. Before a workbook write the agent takes the writer token (rule 7). Other agents work on copies in work/ and hand results over through build/. Exception: fetch agents may add NEW files to Desktop/Tracker library (add-only; never the workbook, never Documents) and log each add to lib/work/library_adds.csv (DECISIONS 2026-10-27, "every NEW page fetched via TinyFish").
2. **Claim before you work.** A task is yours only when BOARD.md lists you as owner. Don't edit files owned by another task.
3. **Log in your own status file.** Write what you did, what's left, and any question for Sammy in status/<agent>.md. Never edit another agent's status file.
4. **Don't decide for Sammy.** If something isn't in DECISIONS.md, write the question in your status file and keep working on what doesn't depend on it.
5. **Contract changes go through the coordinator.** If you need a field that isn't in CONTRACT.md, propose it in your status file.
6. **Verify, don't assume.** Every task ends with a self-check written into its status file: counts, sample comparisons, test results.
7. **Workbook writes.** The master is ~/Desktop/Tracker library/AJG Coverage - NewsBank.xlsx (since 2026-10-27; backups in Tracker library/Backups/; the Documents copy is old and no longer updated). Sammy closes Excel first. Take the writer token: write your agent name to lib/work/WORKBOOK_WRITER.txt only if it reads "none", re-stage, write, verify, then set it back to "none". Write to a new, uniquely named file, commit with expectedMtimeMs, then verify the SHA-256 on the Mac. Fill blanks only and never change an existing value unless DECISIONS.md says so. Rebuild the Originals tab after any Coverage change.
8. **Own scratch folder.** Agents keep helper scripts in their own folder (lib/work/tmp_<agent>/), never a shared one. Scratch files on the Mac go in $HOME/mnt/outputs, never in the Tracker library.

## 5. Handoff kit
- **What:** `handoff_kit/` lets a fresh Claude on another account republish the tracker exactly as live, rebuild it byte-identical from source, and keep running the Update button / sheet task (HANDOFF.md 0.3). Code: `code/make_handoff_kit.py` (owner agent-handoffkit); DB re-seed converter `code/db_reseed.py`.
- **When:** regenerate after EVERY publish to the live tracker (and after a workbook write, so source/work/coverage_current.xlsx matches the master). The publishing agent does both steps:
  1. `record`: save the Artifact `list` scope "files" output of the live tracker verbatim to `build/handoff/live_listing.txt`, then `python3 -I code/make_handoff_kit.py record --listing build/handoff/live_listing.txt --map <the publish map(s) just used>`. This updates the ledger `build/handoff/ledger.json` (every live path, bytes, sha256, contentType, capabilities) and copies the live files into the content store `work/live_store/<sha256>`. Exit 2 = some live file has no local copy: read the paths in `build/handoff/need_fetch.json` with Artifact `read` + `paths` (out_dir `work/handoff_fetch`, ≤64 MB a call) and re-run with `--fetched work/handoff_fetch`.
  2. `build`: `bash build/build.sh --kit` assembles `handoff_kit/publish/` (+ MANIFEST.tsv, capabilities.json, BATCHES.json) and `handoff_kit/source/`, runs the clean-folder rebuild test (build.sh LIB + PIPELINE page sha = live page sha; make_copies reproduces articles/ + img/100+; pipeline/ and data/ compared; apply_all --check), and writes `handoff_kit/parts/` (zips ≤90 MB, SHA256SUMS.txt, KIT_README.md). Exit 3 = rebuild test failed (handoff_kit/REBUILD_TEST.json says what). A pipeline difference just means source changes not yet published.
  3. `make_viewer.py <built index.html> <out dir>` (VIEWER-v1; arguments and the new-account server-side copy step: HANDOFF 4.4a): the shareable viewer copy https://claude.ai/artifact/6vhKKcNXarhSKwnCMk3Bks is rebuilt from the same index.html and republished after every tracker publish (see DECISIONS VIEWER-v1 and HANDOFF 4.4).
- **START_HERE.md and the facts block:** `build` renders L/START_HERE.md into the kit root and source/ with a freshly generated FACTS block (live version, files, MB, master sha, rows, highest IDs, suite count). Do not type those numbers into HANDOFF/README. The storage repack (`code/repack_img.py`, HANDOFF 4.4a) is separate from the kit.
- **DB export (at handoff time only):** export the tracker and review-queue dbs with ArtifactData into `work/db_export/<artifact>/<collection>/<doc_id>.json` (checklist: handoff_kit/source/db_export/EXPORT_CHECKLIST.md), then rebuild the kit; the counts land in KIT_README.
- **What source/ leaves out:** archive/, work/tmp_* scratch (except open handoff/spec/plan/proposal files), build outputs, work/clip, nb_split, library_new, tests_out, build_last, workbook backups. The kit stays in L until the handoff; delivery (outputs folder, Mac `_handoff/`) is a separate step the coordinator orders.
