## Findings, most serious first

**1. The junk and undated-old reprint filters leave the `reprints` documents in place, so the PC save adds the junk rows anyway.**
`src/station.js:573` (`gone` has no `reprints` set) and `:651-656`. The tracker writes one `reprints/rp-<hash>` doc per reprint it adds (`code/tracker/41_update_search.js:1206-1208`), with no `aid`. The PC save's `sheet_task.apply_reprint_docs` (`code/sheet_task.py:1196-1211`, called right after `apply_runs` at `:3689`) adds a Reprint row for every such doc that has no `aid`; `add_row` only skips a doc whose link is already a row. Real folder: 29 reprint docs. After the station's new pass, all 29 are still in `sess.reprints` and all go into the zip (probe: "sess reprints 29", 147 files). That includes `rp-cef3c9cdafc7` (open.spotify.com artist page), `rp-624daa5b7aab` (encinonc.org/page/Board), `rp-ed84eb93a899` (capradio.org/news/?page=11, whose row the station did drop) and the 8 undated old reprints whose rows were dropped (FOX40, Inland Valley News, NewsNation x3, Bloomberg Tax, ABC30, San Mateo Daily Journal). Seven of the 29 never had a row at all (msn.com x3, hankyung, bastillepost 2021, Spotify, board page): those are exactly the rows Sammy saw. The filter therefore removes nothing from what the PC proposes for these.
Fix: in the FILEDUP/JUNK pass, (a) add `reprints: new Set()` to `gone` and, whenever a Reprint row is removed, add its `_page` id (`rp-...`) to `gone.reprints`; (b) sweep `sess.reprints` itself: delete any doc whose `link` matches `JUNK_URL`, and any doc with no surviving row whose story is older than a month and whose date is blank (same rule as the rows); (c) have `slop_test.js` assert on `sess.reprints` (no Spotify, no board page, no `?page=`) and on the packed `db/reprints/` list.

**2. The first-8-words match turns an unrelated story into a reprint, and the second reconcile pass then deletes it.**
`src/station.js:518` (`fdLead`), `:539` (`near` is true when either side has no date), `:650`. Probe on the real file: a new undated find "California Assembly passes first-in-nation bill to require AI labels on political ads" (outlet Example Daily) was "Filed as a reprint of 03580" (a years-old story that starts with the same 8 words); on the next `xdReconcile` (which `pack()` always runs) the now-undated reprint of an old story was removed by UNDATEDOLD-v1. Net effect: a genuine new story vanishes, with no visible reason (see 4). The tracker has 871 first-8-word keys shared by two or more rows ("california assembly passes first in nation bill to" alone covers 24 rows across years) and 584 rows with no date, so `near` is true for them against any find, dated or not. Same-outlet variant: the find is dropped outright at `:663`.
Fix: use the first-8-words key only when both the find and the row have full dates (then the 14-day window holds); let the full-headline key tolerate one missing date. Never let a row the station itself converted to a Reprint be dropped by UNDATEDOLD-v1 (mark it, e.g. `_filedup: true`, and skip it at `:650`).

**3. Finds dated before the search start still go in as new stories.**
Of the 17 old Originals in the real run, 11 have `_date_src: 'claude'`: they had no date when the tracker's page-date filter ran (`41_update_search.js:1004`) and got their date later from Claude's review, which is never checked against `since`. After the station's pass they are all still in the folder as new (KTLA 2019, Haaretz 2018, Los Angeles Times 2012, Epoch Times 2018-2023, JD Supra 2024, OC Register 2026-01, KFI 2026-04). NEWEST-v1 does remove the cause for most of them (16 of 17 are "found by outlet backfill", and the manual-date mode keeps `after_date` on every search and skips the all-time sweeps), but anything a search engine returns without a date still passes `sinceKeep` and can come back dated 2019 by Claude. URLDATE-v1 even dates a row and then keeps it regardless of the date.
Fix: in the station pass, after URL dating, leave out (with a reason in `left`) an Original whose Date is before `S.since` minus a grace of 30 days, unless it is a NewsBank/ProQuest/print row. A reprint of an existing story may keep its old date (the tracker groups reprints under the story).

**4. The new "left out" reasons are thrown away for any big run.**
`src/station.js:655, :670` (and the older `:603, :634`): `d.left = d.left.concat([...]).slice(0, 150)` keeps the first 150 entries. The tracker's own run doc already holds 150 (`left 150` in the real folder), so every station reason is cut off (probe: `left 150`, tail shows only the tracker's reasons). Sammy will see 10 rows missing from the PC preview with no explanation.
Fix: keep the newest, e.g. `.concat(...).slice(-150)`, or put the station's entries first.

**5. A manual date on every run switches off the "search did not finish" warning.**
`src/newsbank.js:518-524` passes `since`, so `RA.sinceManual` is set (`42_update_buttons.js:16`), the run doc gets `since_manual: true` and `searched_to: ''` (`:78-79`). `src/station.js:70` (`if (d.since_manual) return;`) then skips `ended_early` for every station run, so STFIX 5's red note and the folder's "A web search in this folder did not finish" warning can never appear; a stopped or failing run looks like "nothing new". Side effect: `searched_to` never advances, so the for-Update file's `memory.searched_to` is frozen (harmless now, but the PC's "last full update" record stops meaning anything).
Fix: have the override set a flag (`window.__stationAutoSince = true`) and make `markEnd` treat `d.since === S.since` as the normal case: run the ended-early checks and, when the run was clean, treat it as finished (the station can write its own `searched_to` / note).

**6. URL date parser: a one-digit day followed by a hyphen is read as a date.**
`src/station.js:546`: `/\/(19|20)\d\d\/(\d{1,2})\/(\d{1,2})(?:\/|$|[^\d])/`. Probe: `.../2024/1/5-things-to-know-about-the-budget` became 2024-01-05 (Date source "URL"). "5 things", "3 takeaways" slugs under `/yyyy/m/` are common.
Fix: after the day require `/`, end of string or `?`/`#`; accept a hyphen only after a two-digit day.

**7. "Date source: URL" is overwritten on the PC.**
`src/station.js:647` sets the `Date source` column but not `_date_src`. The save derives Date source from `obj._date_src` (`code/sheet_task.py:1078, :1098-1100`; `date_rules.source_from_update` maps `'url'` to `'URL'`), so a URL-dated row lands as "unknown" (or "undated" when the tracker had set `_date_src: 'none'`), and check 2 (`date_rules.py:73`) may flag it for review when the date is within 3 days of the run day. Fix: also set `r._date_src = 'url'`.

**8. Same-outlet test by substring drops rows that should be reprints.**
`src/station.js:541`: `e.o.includes(o) || o.includes(e.o)` after stripping to letters. "cbs" is inside "cbsnews", "news" inside "dailynews", "patch" inside "encinopatch": a different outlet counts as the same one and the find is left out instead of filed as a reprint. Fix: exact match after normalisation, plus the tracker's own `covOutlet` / `fdNormO` aliases; allow a substring only when the shorter name has at least 6 letters.

**9. FULLTR-v1: no busy state while translating, so Download can run twice, and the progress text is overwritten every second.**
`src/station.js:408-415`: `fullTranslations` runs before `S.busyPack = true`; `pack()`'s re-entry guard is `S.busyPack`, and `updatePackUi` (`:366`, on a 1 s timer) replaces "Translating story 3 of 11" with "Ready: ...". With 11 non-English stories (the real run) that is several minutes of Claude calls with the button still live; a second click starts a second translation loop and a second zip. Fix: set `S.busyPack = true` (and disable the button) before `xdReconcile`/`fullTranslations`, and have `updatePackUi` leave the status alone while `S.busyPack`. Also: prompts reached 10 KB in the probe and the cap is 24,000 characters while the tracker's own `translateStory` caps at 15,000 (`code/tracker/20_translation.js:68`); a 24 KB input plus a 30 KB JSON answer is where `sample.json` answers get cut and parse fails (then the summary stays, which is the right fallback, but the call was wasted). Match the tracker's cap or split long stories. A failed translation is retried on every later download (cost); acceptable, but say so in the warning.

**10. The station's `d.reprints` entries use a different key than the tracker's.**
`src/station.js:679` writes `{story: hit.code || hit.sid}` (a `jg-` code), the tracker writes the story id (`s02513`) (`41_update_search.js:1224`). Probe: `{"story":"jg-a3f86a","outlet":"SFGATE"}` next to `{"story":"s01513",...}`. The PC save does not read this list, so only the station's own counts are affected; use `hit.sid` for consistency.
