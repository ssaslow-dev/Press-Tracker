How it works

The whole flow

This page finds new stories about Jesse Gabriel and packs them into an update folder (one zip). You drag that zip into the PC tracker with “Bring in update”; the PC tracker checks it and writes the workbook. This page never changes your workbook or your article library.

Step 1: the “for Update” file

The PC tracker makes this file (“Make for Update file”). It lists the stories already in the tracker (headlines, outlets, dates, links, authors, tone and the like) and no article text. The page reads it in your browser; it is not uploaded or stored online. Every duplicate check, and the decision whether a copy is a reprint, works from this file, so load a fresh one for each session. If the file is old, the page says so. Loading a different file clears the page.

Step 2: Update

The Update button is the tracker’s own. It runs about 700 searches through TinyFish (25 minutes or more; keep the tab open), drops what the tracker already has, and then Claude reviews each new find: is it a real story about Assemblymember Gabriel, is it a press release, which outlet and date. For each new story Claude also rates tone and topic, splits out the authors and translates a non-English headline. Press releases are judged by who wrote them (an advocacy group’s or an official’s own release is not press). Free sources only: nothing is logged into and no paywall is bypassed. Pressing Update is never automatic.

Add NewsBank PDFs and newspaper pages

NewsBank “Multiple Articles” PDFs (APA citation format, one to many stories each) are cut into one PDF per story. Each story is checked against the file, rated and translated like a new find, and its publisher’s own web page is looked up with TinyFish (about two calls a story; untick the box to skip). The story’s text becomes the saved copy and the cut-out PDF is kept as its print scan. Files are named with the tracker’s naming rules.

Print pages. A NewsBank “Full Page” is a picture of a newspaper page. Claude reads it in full-size pieces (the page is cut into overlapping tiles so small print stays readable), finds every article that names him and transcribes it. The page is then placed by its own paper, date and page number: it becomes the print original of a row the tracker already has, a print edition (reprint row) of a story already in the tracker, a jump page joined to the page it continues, or a new story. A page that matches a text story in the same batch (same paper, date and page) goes with that story even if Claude finds no article on the picture. A page Claude could not read, or finds no article on, goes to the “Unlinked print pages” list for you to match by hand. Pictures that are byte-for-byte the same are read once. Any other newspaper page (an e-edition PDF, a scan, a photo) is read the same way, with the paper and date taken from the masthead; if they are not clear, the page is only listed and nothing is added.

Add ProQuest PDFs

One article per PDF, or an export of several articles (up to 20 per PDF is best; more still works, only slower). A PDF with several articles is cut into one article each; an article whose details cannot be read is listed as “needs a look” and the others go on. The details block (title, publication, date, ProQuest document ID) is read, and the story is checked against the tracker by that ID and by headline, outlet and date, then rated, translated and given its own web page like any new find.

Duplicates across sources

A story found by the web search, in a NewsBank PDF and in a ProQuest PDF is kept once. A copy that ran later under another outlet is a reprint of the story that ran first, and the earlier one is named as the original. The final text-based reprint test runs on the PC at save time.

The update folder

One zip: the runs, story pages, reprints, authors, translations and tones found since the file was loaded, plus the PDFs and library files, named for the tracker’s library. The PC tracker (“Bring in update”) shows every row for you to review before anything is saved; nothing is written until you save there. If you download again in the same session, the new zip holds everything found so far and replaces the earlier one.

Automatic adding, and what is never automatic

With automatic mode on, PDFs you drop in are added to the update by themselves (after a run that is going has finished). Never automatic: pressing Update, and downloading the update folder. Nothing is scheduled and nothing runs in the background.

Permissions

Claude must be allowed for this page (the Permissions menu); it is also what reads print pages, so the page must be allowed to send pictures to Claude. TinyFish must be connected in claude.ai (Settings, Connectors) and allowed for the page; without it the searches and web-page look-ups are skipped. Claude and TinyFish each ask for your consent on first use. The page asks for no logins or keys.
