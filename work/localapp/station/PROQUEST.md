## 1. What today's library and workbook show

- **The library's ProQuest copies are text, made from PDFs but not the PDFs.** 460 files `data/library/<year>/pq<ID><o|r>-s<ID>.html` (plus 98 older versions in `_original_html/`). Every one has the same shape: `<meta name="jg-pdf" content="" data-pages="N" data-shown="text">`, `<article class="jg-pdf-text">`, `<p class="pdf-cap">Text of the ProQuest PDF (N pages)</p>`, `<h1>headline</h1>`, an optional `<p class="byline">By ...</p>`, then one `<p>` per paragraph. That is the tracker's own PDF-drop code (`code/tracker/06_story_sheet.js`, PDF.js in the Manage panel) in its text-only form. 36 of the library's files still carry `PDF GENERATED BY PROQUEST.COM` / `Page x of y` lines and some a `Publication: ...` line; the reprint rule already sets those aside (HANDOFF 3, "Text of the ProQuest PDF"). The original PDFs were not kept (HANDOFF: 488 ProQuest PDFs became text copies; DECISIONS line 40: "ProQuest: tracker text copies saved as pq...html; the 6 real PDFs as .pdf"). No `pq*.pdf` exists in the snapshot.
- **`_original_pdf/<year>/` is for raw print jump pages** (`<aid>_p<page>.pdf`, 31 files in 2026), not for article PDFs. `_original_html/<year>/` holds the uncleaned page under the *same file name* as the saved copy.
- **ProQuest rows in the snapshot workbook.** 336 rows have `Data Source` = `ProQuest` (271 Originals, 65 Reprints); 473 rows carry a `ProQuest link` (132 NewsBank rows hold one as a second source: `File type 2` / `File name 2`). - **The tracker already indexes ProQuest links**: `covLoad` keeps the query on `proquest` hosts, so `covLink('https://www.proquest.com/docview/<id>')` finds a row by its ProQuest id (that is the "link index" the dedupe uses). 389 of the 3,681 stories have a `pq` link in the for-Update file.

## 2. What it does (card "Add ProQuest PDFs", after the NewsBank card)

Drop any number of PDFs (one article each). For each file, in the browser:

1. **Read** with the same pinned pdf.js 4.10.38 as the NewsBank card (no worker, no eval, no outside code) and the same line builder (`NBParse.linesFromItems`). A file that is not a PDF, is password-protected or cannot be opened is listed with that reason in plain words. A file byte-identical to one already dropped is skipped ("identical to ...").
2. **Parse the details** (`src/pqparse.js`, pure functions, node-tested). Nothing is taken from outside the PDF. English labels, in any order, with or without colons for the unmistakable ones:
   - Fields read: Title, Author(s), Publication title, Publication date (or year), Section, Pages (or First page), Publisher, Place of publication, ISSN, Source type, Document type, Language of publication, ProQuest document ID, Document URL, Copyright, Database; any other "Label: value" line inside the block (Subject, Number of pages, Identifier / keyword ...) belongs to the block and is ignored.
   - The block may sit before the text (a citation/metadata first page) or after it ("Details"), may wrap long values (Title, Document URL), may spill onto a second page, and may put a value on the line after its label. A "Full text" line ends the block, so article text that happens to start with "Section: ..." is not taken as metadata. Page furniture (`PDF GENERATED BY PROQUEST.COM`, `Page x of y`, a repeated running head) is removed from the text.
   - **Headline** = the Title field. With no Title field the large heading at the top of the text is used and the story is marked "check". **Date** = the publication date with a day (`Sep 13, 2024`, `13 Sep 2024`, `September 13, 2024`, `2024-09-13`). **Outlet** = the publication title before the first `;`, edition suffixes removed (`New York Times, Late Edition (East Coast); New York, N.Y.` becomes `New York Times`); the tracker's own `covOutletName` then writes it NewsBank style ("Center Square, The"). **Author** "Last, First; Last, First" becomes the sheet's form "First Last and First Last". **Document id** = the ProQuest document ID line, else the number after `/docview/` in the Document URL; if both are present and differ, the PDF "needs a look".
3. **Decide what it is.** `ok`, or one of:
   - *Needs a look* (listed in grey-red, no checkbox, not added, never guessed): no readable text (scanned image); no headline, no publication title or no publication date; a date with no day ("Sep 2026"); more than one article in the PDF (more than one document ID); document ID and URL that disagree.
   - *Not a ProQuest article PDF*: no ProQuest details block and no "proquest" anywhere in the text. A NewsBank PDF gets a pointer to the NewsBank box (and a ProQuest PDF dropped in the NewsBank box is refused there: "no Citation (apa Style) block").
4. **Is it already in the tracker?** (`nbScreen` with the ProQuest source object; the tracker's own functions): (1) by ProQuest document id against every link of every Coverage row, story and reprint (`pqIds`, built from `covLoad` and the stories); (2) the same id earlier among the PDFs dropped this session ("Twice in these PDFs": a second download of the same article with different bytes is caught here); (3) `covLink` on the canonical link, then `covHit` (same outlet and headline within 3 days is "already in the tracker"; another outlet with the same headline is a **reprint** of that story) and `dupOf` against stories added this session. A PDF with no document id is checked by headline, outlet and date only and says so.
5. **Rate it**: `nbRun` (newsbank.js, now driven by a source object) does exactly what it does for NewsBank: Claude via `sample` in batches of 20 with the tracker's own `classifyPrompt` and a ProQuest preface (copy ProQuest's date, outlet and headline; the first line of each text lists ProQuest's own details, so "Wire Feed" reads as Wire and the language is known; a full text that does not name Jesse Gabriel the Assemblymember, another Jesse Gabriel, or not press is dropped and listed once); topic, tone, role, language, English headline and summary; the tracker's own headline translation pass; the publisher's own page (TinyFish search per headline, then one `fetch_content` per 10 candidates: a page that shares two 6-word runs with the PDF's text, or has host evidence plus his name, becomes `Publisher URL`; a blocked page with a strong host match is **kept** as `Search link only`; nothing found leaves both blank and the Team note says why); the originator lookup (`originCredit`); proposed rows with `proposeRows`; reprint rows with their own `rp-` pages doc and a `reprints` doc (the PC decides by the string-of-text rule at save time, never the station).
6. **Pack**: each story's pages doc (text + details) and its PDF go in the update folder (`files/pq-<16 hex>.pdf`), and the run doc has `mode: "hand"`, `proquest: <date>`. Step 3 counts "N ProQuest PDFs". The 180 MB-per-update guard counts NewsBank and ProQuest PDFs together; while one card is adding, the other's button is off.

Rows: `Data Source` `ProQuest`; `Date source` `ProQuest`, or `print edition` when the PDF gives a page *and* the source type is a newspaper, magazine, journal or trade paper (then `Edition` and `Format` are `Print` too; a wire feed or website with a page stays plain); `ProQuest link` and `ProQuest via CA State Library` in the sheet's forms (blank, with a note, when the PDF has no id); `Section` and `Page` are filled when the PDF has them (the existing ProQuest rows leave both empty: this adds information, never replaces a value). FORMAT.md section 2c has the full shapes.

## 3. The library form (decided)

- **The saved copy is `<year>/pq<Article ID><o|r>-<Story ID>.html`, built from the PDF's text the way the existing `pq*.html` look** (`PQParse.storyHtml`: same meta, same `jg-pdf-text` article, same "Text of the ProQuest PDF (N pages)" caption, h1, byline, paragraphs; no details block, no footer lines). So Clips search, the viewer, the reprint rule and the "Original's own text" choice work exactly as for today's ProQuest rows. `File type` is `ProQuest pdf` (the sheet's own word), `Saved Copy?` Yes, `Data Source` `ProQuest`.
- **The PDF is kept too: `_original_pdf/<year>/pq<Article ID><o|r>-<Story ID>.pdf`**, add-only. Why there: that folder is already "raw PDF downloads"; the name matches the saved copy's (as `_original_html/<year>/` does for HTML), and it cannot be mistaken for a print jump page (`<aid>_p<page>.pdf`). The saver already copies everything under the pages folder add-only, so nothing changes in the saver. A name that already exists is skipped and listed (SAVE_RULES answer 3).
- **What "original" means here**: the station does not pass the dropped file's bytes through. It copies the pages into a new PDF (pdf-lib), leaving out links, annotations, actions and page metadata, because the PC refuses any PDF with `/OpenAction`, `/JavaScript`, `/Launch`, embedded files and similar, and a real ProQuest PDF might carry a benign `/OpenAction`. The pages themselves are ProQuest's, byte for byte. The pages doc keeps the dropped file's own sha256 and name (`pq.source_sha256`, `pq.source_name`). If Sammy wants the exact bytes, the station would have to pass them through and the PC would have to accept benign actions: a separate decision (section 7).
- If the PDF cannot be copied or is over 24 MB, the text copy is still saved and the PDF is not (the row is flagged `pdf_missing` at save time); a PDF with almost no text is "needs a look" and is not added at all.

## 4. What changed outside the new files

- `src/newsbank.js`: `nbRun`, `nbScreen`, `nbFindLinks`, `nbClassify` take a *source object* (`NBSRC.nb` default, `NBSRC.pq` in `src/proquest.js`). With no source given the NewsBank behaviour is unchanged (the whole NewsBank test set passes).
- `src/newsbank_ui.js`: `nbStoryPdf` takes a label (NewsBank/ProQuest) and **now strips annotations, actions and page metadata from the source pages before copying**. ## 6. What a real ProQuest PDF must show (please get one, ideally three kinds)

Send the output of `pdftotext -layout` for: **(a)** a normal newspaper article from ProQuest Central (a Los Angeles Times or New York Times item), **(b)** a wire or web-only item (Center Square, JTA, a TCA/Tribune item), **(c)** a non-English item, plus each file's page count. Then check these, because the parser assumes them:

1. The details are lines of `Label: value` in English (`Publication title:`, `Publication date:`, `ProQuest document ID:` ...). If the labels are in a two-column table that the text layer reads column by column (all the labels, then all the values), the parser will report "Could not read ..." and not add the story: it never guesses.
2. The Title field is present. If it is not, the large heading is used (marked "check").
3. The text is real text (not a page image). Scanned or "Full Text - PDF" page-image files (typical of historical newspapers) have no text layer: they are "needs a look".
4. The publication date has a day, in a form like `Sep 13, 2024`. A magazine that gives `Sep 2024` is "needs a look".
5. `ProQuest document ID` or `Document URL` is present (otherwise the story is added without a ProQuest link and checked by headline only).
6. Where the "Full text" marker sits (`FULL TEXT` above the text; nothing needed if absent), and what page furniture repeats on every page.
7. For a print item: whether `Pages:` (or `First page:`) gives the print page (`A3`, `B1`). That decides Edition Print.
8. Several articles in one PDF would be refused; ProQuest's "Print/Save" of selected items may do that.

## 7. Open questions for Sammy

1. **Exact original bytes or the cleaned copy?** (section 3). Default built: the cleaned copy (pages identical, no links/actions), with the dropped file's checksum recorded.
2. **Section and Page on ProQuest rows**: today empty on all 336; the station fills them when the PDF has them. Say if they should stay empty.
3. **Print rule**: a page number on a newspaper/magazine/journal source makes Edition/Format `Print` and Date source `print edition`, as the existing rows do for NYT print items; a wire or website with a page stays plain. Needs a real PDF to confirm.
4. **Outlet names differ between databases** ("The Center Square; Washington" in ProQuest, "Center Square California, The" in NewsBank). A ProQuest copy of a story the tracker already has from NewsBank under the NewsBank name is found by headline and called a *reprint candidate* unless the ProQuest id is already on the row. The PC's text test then decides, and its same-outlet rule applies. If interns will drop ProQuest PDFs of stories that already came in from NewsBank, an alias list (ProQuest name -> NewsBank name) would remove the false reprints.
5. **Run doc mode**: `hand` ("Added by hand" in the run log) is used because the page turns unknown modes into "find". Say if the log should read differently (needs a one-word change in the tracker's log code, which this build does not touch).
6. **Interns**: the same sharing and connector notes as NewsBank (NEWSBANK.md 2.6) apply; ProQuest PDFs are licensed content: the update zip must not go behind a public link.
