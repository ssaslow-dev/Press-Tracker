# Blind audit: "Updating the tracker with the Update station" (20 pages, 2026-11-05)

**Verdict:** Clear, well ordered and close to the real station; printable after fixing six things that would mislead a reader (a link that will change, one screenshot that contradicts its caption, fingerprints that disagree from page to page, the "Use it anyway" order, Safari unzipping the folder on the Mac, and the station forgetting everything when the tab closes).

Checked against: `work/localapp/station/src/station.html` (How it works), `station.js`, `newsbank.js`, `newsbank_ui.js`, `app/src/station/web/panel.js`, `app/src/station/plain.py`, `MOVE_TO_OFFICE.md`, and the NewsBank Download Guide PDF for style. Page images at 110 dpi, with 200 dpi renders of pages 5, 7, 9 and 10 for type sizes.

What is right and need not change: the two-week search window (`SINCE_OVERLAP_DAYS = 14`; the p6 shot shows Nov 4 → Oct 21, correct); "no date to pick"; Search all time pressed twice, within a few seconds (6 s in code), turning itself off after the run; Step 2's own button starting at once and the masthead button asking first; the checklist names; the duplicate, reprint, junk-page and URL-date rules on p9; the NewsBank one-in-six line and the Full Page handling; translation of whole stories at download, "Translating story 1 of 2 into English…", the zip name shape and the `_v2` rule; the PC panel wording (section numbers, button names, warning text, "Items that need a person", "Reloading the tracker…"); the Problems table's fixes; the cheat sheet. Fonts, header band, kickers, side-bar callouts, dark callout, tables and footer match the style guide.

## Recommendations, most important first

1. **Pages 3, 5 (and 20): the station link will stop working.** The printed link (`claude.ai/artifact/5uGsM8yQMphjAQbKhvc5SL`) is the private artifact on the current account. `MOVE_TO_OFFICE.md` says the station is to be republished on the office account, which gives a new link, and the guide tells the reader to sign in with the office account, where this link does not open. Change: print the link once, after the office publish, or leave a filled-in line ("Station link: ______ (the keeper has it)") and keep the "ask the keeper" wording. Do not print the current link in a guide that says "office account".

2. **Page 10: the screenshot contradicts its caption.** The caption says "After the first press: press again to start", but the button in the shot reads plain "Search all time" (checked at 200 dpi). The armed label is "Search all time: press again to start" and lasts 6 seconds. Change: re-shoot inside those 6 seconds (or set the label by hand as on other pages and say so), or drop the shot; the text already says what the label becomes. Add "within about 6 seconds" to step 2, and that during the run the button reads "Searching all time…".

3. **Pages 4, 5-6, 12, 13, 16, 17: the staged fingerprints tell an impossible story.** The guide defines "Fingerprint" (p2) and teaches the reader to compare codes (p4 file name, p12 zip name, p13 warning). But: the for-Update file on p4 is `41315fe0` with 3,689 stories; the station on p5-6 has loaded a different file, `83614b19`, 3,832 stories; the zip on p12 is `83614b19`; the PC warning on p13 compares `c252cc92` with `bc21c9fb`; the save on p16 ends with "New workbook fingerprint: 41315fe0", the same code the workbook had *before* the run on p4; p17's refresh file is `41315fe0` too. A reader who follows the codes concludes the save changed nothing or the wrong zip was used. Change: re-stage one run end to end and use its shots, or add one sentence on p1 or p2 ("The screenshots come from several test runs, so the codes and counts differ from page to page") and at least fix p16 so the post-save fingerprint is not the p4 one.

4. **Page 13 (and p18, last row): "Use it anyway" is offered first and reads as the default.** The warning itself says stories "may already be in the workbook, or others may be missing". Change step 4 to lead with the clean fix: "Press Do not use it, make a new 'for Update' file and run the station again. If you cannot rerun, Use it anyway: the save still fills blanks only and checks the texts, but read the preview more carefully for stories the workbook already has." Same order in the p18 row "The PC warns the update was made from a different workbook".

5. **Pages 12 and 19: Safari on the Mac unzips the update folder by itself.** The station part runs on a Mac (p3), and Safari's "Open 'safe' files after downloading" turns the .zip into a folder; the PC then says "That is not a .zip file" (its message even names Safari). The guide says "Don't unzip it" but not that the browser may do it. Change: in p12 step 6 add "On a Mac, use Chrome, or turn off Safari > Settings > General > Open 'safe' files after downloading; if a folder appeared instead of a .zip, turn that off and press Download the last one again." Add the same to the p19 row.

6. **Pages 6 and 18: nothing says that the station forgets everything.** "Load a different file" clears the page *including runs not yet downloaded* (the button asks for a second click to confirm), and closing the tab loses whatever was found but not downloaded (How it works: "it keeps nothing after you close it"). Change: under the p6 bullets add "Load a different file clears the page, including anything found and not yet downloaded; it asks you to click again." In p18's "You closed the station tab during a run" add "Anything it found and you had not downloaded is gone." Consider a one-line "Download before you close the tab" in the p3 dark callout.

7. **Page 9: the left-out rules are incomplete.** Code also drops a web find dated more than a month before the search start (OLDFIND-v1; not during Search all time), and every left-out row is listed with its reason in the PC preview. Change the last bullet to: "A reprint with no date of a story more than a month old is left out, and so is a web find dated more than a month before the search start (not in Search all time). A row with no date takes the date in its web address when it has one. Every left-out row is listed, with the reason, in the PC tracker's preview."

8. **Page 7: the How it works screenshot is already out of date.** The station now says "Step 2: Update database", "keeps nothing after you close it", "Press it twice to start (the first press asks you to confirm)" and the one-month rule; the shot has none of these. A full-page picture of text will go stale at every republish. Change: cut the page to a short paragraph ("How it works opens the station's own explanation; it covers what pages 6-12 cover, plus Automatic mode and what to do if something is blocked") and drop the shot, or re-shoot last, after the station text settles.

9. **Page 5: the screenshot is too small to read on paper.** The whole station at half column width puts the gray captions, "STEP 1 ✓" and the fact labels at about 5-6 pt; the "green check mark" the caption points at is about 2 mm. Page 6 shows the same Step 1 panel full width. Change: on p5 show only the drop box state ("Drop the file here, or click to choose it"), full width, which the guide never shows and is the one state the reader meets first; leave the loaded state to p6.

10. **All screenshots: match the style guide's orange outlines.** The NewsBank guide draws an orange box around every control a step names (Date Search, Sort by, the download arrow). This guide's shots have none, so the reader hunts for Stop, Search all time, Use it anyway, Save. Change: outline the control each step names on p4, 5, 8, 10, 11, 12, 13, 15 and 17. Optional: zebra-stripe the table rows as the style guide does.

11. **Page 12 vs page 11: Automatic mode.** Page 11 says it is on by default (true: `localStorage` remembers the choice); the p12 shot shows it unchecked. Change: re-shoot with it on, or say in the caption it was switched off for the shot. Add "the station remembers your choice in that browser" to p11 step 3.

12. **Page 3, item 5: the first-time permissions are the likeliest blocker and have no picture.** Change: add a small shot of the artifact page's Permissions menu and of the TinyFish/Claude allow prompt (or at least say where the menu is), and say the connector must be named exactly "TinyFish" (How it works says so; it matters when the office account is set up).

13. **Page 14, bullet 3: wrong phrase.** "Conflicts left for the keeper to decide" is not what the screen says; the PC lists "cells where the update disagrees with the workbook (the workbook keeps its value)", which p15's table has right. Change the bullet to the on-screen phrase. Bullet 1 says the bold line counts "your own waiting edits"; in the shot the edits are a bullet below it, not in the bold line.

14. **Pages 15-16: "check those rows in the workbook" with no place named.** The p16 shot ends "10 items are listed for a person to look at (see the run notes)" and the guide never says where the run notes are. Change: name the place (Manage's Update log, or the file under `data\` if that is where they land) in p15's paragraph and p16's caption.

15. **Page 8, step 2: "in front" and "use other programs" pull against each other.** Change to the style guide's wording: "Keep the browser window with the station tab visible on screen and the computer awake; don't minimise it or switch to another tab in that window. Other programs beside it are fine."

16. **Page 11, last bullet: only true with Automatic mode on.** With it off, "Add to the update" during a run refuses with "A web search is running: the PDFs are added after it finishes". Change: "If a run is going, the PDFs wait for it (Automatic mode), or press Add to the update again when the run is done."

17. **Page 18, row "The search finds nothing or stops at once": quote the real message.** The station shows a red "Stopped. TinyFish is not connected on this account. In claude.ai open Settings, Connectors, connect TinyFish, then reload this page." (and "The TinyFish connection has lapsed. Reconnect…"). Put that text in the left column so it can be matched, and add "then reload the page and press Update database again" on the right.

18. **Page 16: an unexplained line in the shot.** "0 file name(s) were as the station named them." will puzzle a reader. Change: crop it out or add to the caption "(the file-naming check; 0 because this test update carried no new files)". Likewise p17's "refresh_full_0002…" next to "this is the first refresh file": say what 0002 counts, or re-shoot.

19. **Pages 2, 7 and 19: a third of the paper is blank.** Page 2 is two-thirds empty, p7 is one screenshot, p19 has three table rows. The style guide puts Problems and the cheat sheet on one page. Change: pull the Words table onto p1 or p2's upper half, drop p7 (see 8), and tighten the Problems table so the cheat sheet sits under it; 17 pages is reachable.

20. **Page 1 table: page order.** "Make the file" points to p4 and the next row "Move the file" back to p3; moving the file is actually described on p3's box and p4 step 5. Change the row's page to 4, or fold the row into "Make the file".

21. **Page 4 and 12: say what the file names mean once.** `202611052016` = 2026-11-05, 8:16 PM; the zip's `20261105-2021` has a different shape. One sentence on p4 ("the year, month, day, hour and minute") saves the reader working it out.

22. **Page 15, step 2: match the screen's name for the window.** The PC says "Do not close the Terminal or command window"; the guide says "the black window". Use "the black command window (the one the tracker opened)" so both read as the same thing.

23. **Page 6: the age line turns red.** The "File made…" line goes red when the file is more than 7 days old or has no date. One clause: "It turns red when the file is over a week old: make a new one."

Not misleading, no change needed: p9's "(example numbers)" is declared; the PC panel shots reused across p13-17 are fine in themselves apart from the fingerprint sequence in item 3; the embedded font names read "PublicSansThin-*" but the CSS loads the same Public Sans files as the style guide, and the printed weight matches.
