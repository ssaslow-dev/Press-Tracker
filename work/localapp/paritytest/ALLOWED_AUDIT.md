The latest run read as output: scratchpad `paritytest_out/parity/1440x900_summary.json` (pt6, 2026-11-04 01:23): 19 interactions, 0 differences, 0 allowed, no crash, PASS.

## Verdict

Mostly sound. `allowed.json` is empty, crashes count as failures, there is no pixel tolerance, and every element the reference hides is one of the recorded buttons. But four suppressions are wider than their decision, and two recorded exceptions (Last updated, View original) pass only because the test data never shows them. Fix the four items marked **yes** below before the test is called a proof; the rest are notes.

## Coverage gaps, highest risk first

1. **Last updated and View original are never on screen.** The test build has no save in its ledger (`last_updated` is "") and no `_original_pdf` files (0 rows carry `po`), so LASTUPDATED-v1 and VIEWORIG-v1 pass without being shown, and their exceptions (#2, #11) are untested. Only `app/tests/test_step2.py` checks Last updated, on the PC alone. Fix: build the test copy with one ledger save entry and one print original, then add the narrow exceptions.
2. **Dark mode.** TIDY-v1 (1) says "light and dark"; neither check sets `prefers-color-scheme: dark`. test_tidy.py samples header edges in dark on the PC alone; no side-by-side.
3. **Reader copies.** Every run uses `make_work(…, 'keeper')`. MULTIPC-v2 reader copies (panel hides the save buttons, reader note) are never compared with the live page.
4. **Clipboard copies** can pass on the reference's text (#6).
5. **Remote-photo copies** (PHOTOLINK-v1): the PC viewer code differs (patch 06) but only copies with embedded photos are opened; a copy with linked photos is never compared (noted in the look check README; needs the internet).
6. **Narrow width behaviour.** run_paritytest runs 1440x900 only; TIDY-v1 (2) and the Reporters column drop (#3) are 761-1299 px rules. The look check covers 960x1040 for pixels; behaviour at that width only through run_lookcheck.
7. **Tracker files panel actions** (Bring in update, Save my edits, Make refresh file, Accept the workbook) have no live counterpart in the page, so parity cannot compare them; they rest on CHAINCHECK-v1 and the app tests. Expected, but it means PCEDITS-v1's "same checks as any save" is not proven here.
8. Edits: only headline, topic, tone and note are changed; removal is not undone; a reprint row is not edited.
