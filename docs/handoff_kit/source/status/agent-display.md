## Issues for the coordinator (T2 data, not JS)
1. **`pub` changed meaning, and the change is visible.** The old `r.pub` was the outlet's short name (e.g. "JNS", "Encino Enterprise"). It drives the Outlet facet, outlet charts and ranking. The new data's `pub` is the sheet's Publisher: a parent company ("McClatchy", "Southern California News Group"), or blank on 863 stories. Only 2,360 of 4,296 have pub = outlet. Suggest build_data set `pub` from the old record when `code` exists, else from Outlet. Otherwise the Outlet facet lists parent companies.
2. **Outlet spelling.** Outlets are now NewsBank style ("Sacramento Bee, The") where the tracker showed "The Sacramento Bee". This is Sammy's own sheet convention, but it is a visible change; flag it to him.
3. **Count vs list.** The count uses the sheet's "# of reprints". In 36 of 1,082 stories the "Reprinted in" list has a different length, because the sheet merges alias outlets (Politico = Politico Pro, AP feeds, CNN Wire = CNN, FoodNavigator variants) that JS can't know. If they must match exactly, have build_data mark alias reps (`same:true`) and I'd filter them in `repNames`.
4. The build's `rc` (list of county strings) is ignored; the JS rebuilds pairs from `reps`. `county` on a record should stay CA-only to match the old map. Please confirm that build_data only puts CA counties in `county`.
